# kenton-reverse-lens 故障排查

按“症状 → 原因 → 安全检查 → 修复 → 恢复验证”的顺序处理。

## 可用 Skill 列表中没有 `kenton-reverse-lens`

**常见原因**

- `kenton-reverse-lens` 目录没有放在宿主要求的 Skills 目录；
- 文件被多套了一层目录；
- 宿主仍在使用旧会话或缓存；
- 宿主不支持本项目采用的 `SKILL.md` 结构。

**安全检查**

确认目标目录中直接存在 `SKILL.md`，并且 frontmatter 中是：

```yaml
name: kenton-reverse-lens
```

**修复**

按宿主官方文档调整目录位置，然后重新启动宿主或开启新会话。

**恢复验证**

可用 Skill 列表中出现 `kenton-reverse-lens`，再用一条可完整读取的材料测试。

## 输出只有人物摘要，没有反向分析

**常见原因**

- Skill 未被实际加载；
- 请求被宿主当成普通摘要；
- 没有提供自己的品牌目标。

**安全检查**

检查输出是否同时包含“他的想法 / 做法 / 方向”和“反向分析”。

**修复**

补充品牌目标，并明确要求先剥时代外壳，再回答怎么做、怎么搭建、怎么思考。

**恢复验证**

输出出现完整两段，并把外部方法转成适合当前品牌尺度的行动与能力结构。

## 建议只是照抄大团队或资本级打法

**常见原因**

- 跳过了“第 0 步：剥时代外壳”；
- 把资源规模误当成可迁移的方法；
- 没有使用“一个人 + AI”的约束。

**安全检查**

标出每项建议依赖的人力、资本、媒体位和组织规模。

**修复**

删除不可获得的时代外壳，只保留定位、杠杆和可在当前尺度运行的不变量。

**恢复验证**

每项建议都能说明在“一个人 + AI”条件下如何执行，或明确标为当前不可行。

## 事实、ASR 噪声和推断混在一起

**常见原因**

- 转写稿存在同音错字；
- 人物身份被标题或剪辑误导；
- 战略判断没有标记为推断。

**安全检查**

回到原视频、原文或可靠身份来源，逐项核对矛盾处。不要用猜测补空白。

**修复**

修正有证据的事实；无法确认的内容标为 `⚪ 推断` 或“待核对”。

**恢复验证**

读者能清楚区分原始事实、转写噪声和反向战略判断。

## 无脸剪辑号只分析了运营模式

**常见原因**

- 把搬运内容当成低价值素材；
- 忽略了内容中可能存在的高密度方法论。

**安全检查**

分别检查“账号如何运营”和“被剪辑人物说了什么”。

**修复**

补做内容方法论层，提取定位、杠杆和可迁移不变量，再与运营模式层交叉分析。

**恢复验证**

输出同时存在运营模式层和内容方法论层，并说明两者的连接或冲突。

## Agent 试图无人值守地产出最终战略

**常见原因**

- 把抓取、转写自动化误等同于战略判断自动化；
- 没有保留人在场的校准环节。

**安全检查**

区分可自动化的数据准备与需要判断的反向分析。

**修复**

暂停无人值守的最终分析，只自动化来源清单、抓取和转写准备；在有人参与的会话中完成战略推演。

**恢复验证**

最终结论在交互会话内形成，关键假设、取舍和推断均可被人核对。
